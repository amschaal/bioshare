# Documentation screenshots

Every image in `docs/images/screenshots/` is generated by `capture.js`. Do not
edit them by hand — the point of generating them is that after a UI change you can
re-run the script and see from `git diff` exactly which screens moved.

## Running

Against a **development** instance only.

First create the demo dataset the screenshots show — realistic shares, groups,
accounts, permissions, activity and files. This is a Django management command, so
run it wherever `manage.py` runs (the app container), not here:

```sh
python manage.py seed_docs_demo
```

Then capture:

```sh
cd tools/screenshots
npm ci
npx playwright install chromium     # one-time, ~110 MB
node capture.js
```

And when you are finished, remove the demo data again:

```sh
python manage.py unseed_docs_demo --yes
```

Both commands refuse to run unless `DEBUG` is on, and the teardown only deletes
objects named in `bioshareX/management/commands/_docs_demo.py` — it cannot match a
real share or account. See that module for the full manifest.

This directory lives outside `docs/` on purpose: everything under `docs/` is copied
into the published site, and shipping `node_modules/` to GitHub Pages would be
unfortunate.

Defaults target the devcontainer app at `http://bioshare:9999`. Override with:

| Variable | Default |
|---|---|
| `BIOSHARE_URL` | `http://bioshare:9999` |
| `BIOSHARE_USER` | `test@fake.com` |
| `BIOSHARE_PASSWORD` | `OnlyForTesting1!` |

The script reads only — it never creates or modifies shares. It logs in once and
reuses the session, because the login view is rate limited to 10 attempts per hour
per username and per IP; repeated failed runs will lock you out for a while.

## Adding a screen

Append an entry to `SCREENS` in `capture.js`:

```js
{
    name: 'my-screen',              // becomes my-screen.png
    url: (ctx) => `/bioshare/...`,  // ctx.shareId is discovered at runtime
    waitFor: 'table',               // selector proving the page finished loading
    prepare: async (page) => {},    // optional: clicks needed to reach the state
}
```

Then reference it from a docs page with a standard Markdown image pointing at
`images/screenshots/my-screen.png`.

## Determinism

Runs are meant to be reproducible: fixed 1280×800 viewport, `deviceScaleFactor: 1`,
forced light theme, and animations plus the text caret disabled via an init script.
A second run immediately after the first should leave `git status` clean.

Content still comes from the target database, so screenshots will legitimately
change when the underlying shares change. Capture against an instance whose data
you are happy to publish — share names, owner email addresses and file names are
all visible in the images.
